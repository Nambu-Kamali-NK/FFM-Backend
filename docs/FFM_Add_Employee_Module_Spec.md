# FFM -- Add Employee Module

## End-to-End Technical Specification

**Module:** Employee Management -- Add Employee\
**Service:** Workforce Service\
**Supporting Service:** Identity & Access Service\
**Stack:** ASP.NET Core .NET 8, Clean Architecture, CQRS/MediatR, EF
Core, PostgreSQL, RabbitMQ, Redis, Docker\
**Authentication:** JWT RS256 issued by Identity & Access Service

## 1. Objective

Implement the complete Add Employee flow in Workforce Service.

The flow must: - Authenticate the caller. - Authorize `SYSTEM_ADMIN`,
`ADMIN`, and `MANAGER`. - Validate that `UserId` exists in Identity
Service. - Validate required fields. - Enforce unique `EmployeeCode` and
`UserId`. - Create the employee with `PENDING_ACTIVATION`. - Persist
Employee, AuditLog, and OutboxMessage transactionally. - Store an
`EmployeeCreated` event in the Outbox. - Return `201 Created` with the
Workforce Employee ID. - Support GET Employee by Workforce Employee
ID. - Provide unit/integration/API/database verification. - Work in the
Docker environment.

Do not invent requirements that are not specified.

## 2. Service Ownership

### Identity & Access Service

Owns: - User account - Authentication - JWT issuance - Identity user
role - User status

Existing validation endpoint:

``` http
GET /api/Auth/users/{id}
```

### Workforce Service

Owns: - Employee profile - EmployeeCode - Workforce Employee ID -
Employee status - Employee-to-Identity User relationship - Audit
information - Employee creation integration event

`Identity UserId` and `Workforce Employee.Id` are different identifiers.

## 3. Authorization

Allowed roles:

``` text
SYSTEM_ADMIN
ADMIN
MANAGER
```

Expected behavior:

  Condition                           Response
  --------------------------------- ----------
  Missing/invalid JWT                      401
  Valid JWT but insufficient role          403
  Authorized caller                   Continue

`CreatedBy` / actor identity must come from the authenticated JWT
context, not the request body.

## 4. Add Employee API

``` http
POST /api/v1/Employees
Authorization: Bearer <JWT>
```

Request:

``` json
{
  "employeeCode": "EMP-KAMALI-001",
  "userId": "e0012bf8-3dda-4857-a4da-e953b640e9f2",
  "name": "Kamali",
  "roleId": "00000000-0000-0000-0000-000000000000",
  "orgUnitId": "00000000-0000-0000-0000-000000000000",
  "managerId": null,
  "email": "kamali@gmail.com",
  "mobile": null
}
```

Fields:

  Field          Required   Rule
  -------------- ---------- --------------------------------------
  EmployeeCode   Yes        Required and unique
  UserId         Yes        Valid GUID; must exist in Identity
  Name           Yes        Required
  RoleId         Yes        Valid GUID
  OrgUnitId      Yes        Valid GUID
  ManagerId      No         Optional GUID
  Email          No         Validate if supplied
  Mobile         No         Apply only approved validation rules

Do not add fields not defined by the approved specification.

## 8. Transaction

Employee creation, audit creation, and outbox creation must be in one
database transaction:

``` text
BEGIN
  INSERT Employee
  INSERT AuditLog
  INSERT OutboxMessage
COMMIT
```

On failure:

``` text
ROLLBACK
```

No partial creation may remain.

## 9. AuditLog

Every successful employee creation must create an AuditLog.

Required information:

``` text
EntityType
EntityId
Action
ActorUserId
BeforeState
AfterState
CorrelationId
CreatedAt
```

For creation:

``` text
EntityType = Employee
Action = Created
EntityId = Employee.Id
ActorUserId = authenticated caller
BeforeState = null/empty
CreatedAt = UTC timestamp
```

## 10. Outbox

Create an OutboxMessage with:

``` text
EventType = EmployeeCreated
Processed = false
```

Example payload:

``` json
{
  "Id": "222fea67-66f3-49cb-ac79-691bf4ba33a9",
  "EmployeeCode": "EMP-KAMALI-001",
  "UserId": "e0012bf8-3dda-4857-a4da-e953b640e9f2",
  "Name": "Kamali"
}
```

Flow:

``` text
Employee + AuditLog + Outbox
          ↓
       Commit
          ↓
Background Outbox Publisher
          ↓
       RabbitMQ
          ↓
 EmployeeCreated event
```

Do not require RabbitMQ to be available during the database transaction.

## 15. Tests

### Authentication

-   Unauthenticated request returns 401.
-   Invalid token is rejected.

### Authorization

-   SYSTEM_ADMIN can create.
-   ADMIN can create.
-   MANAGER can create.
-   EMPLOYEE receives 403.

### Validation

-   Missing EmployeeCode rejected.
-   Missing UserId rejected.
-   Missing Name rejected.
-   Missing RoleId rejected.
-   Missing OrgUnitId rejected.
-   Invalid email rejected when supplied.
-   Duplicate EmployeeCode rejected.
-   Duplicate UserId rejected.
-   Non-existing Identity UserId rejected.

### Creation

Verify: - Employee created. - Status is `PENDING_ACTIVATION`. -
CreatedBy is authenticated actor. - CreatedAt populated. - AuditLog
created. - OutboxMessage created. - EventType is `EmployeeCreated`. -
Processed is initially false.

### GET

-   Existing EmployeeId returns 200.
-   Unknown EmployeeId returns 404.
-   Identity UserId is not confused with EmployeeId.
